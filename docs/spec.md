# 모둠 협동 직소 퍼즐 (가칭: 함께 퍼즐)

트랙: 교육
종류: 새 서비스

## 목적

초등 교실에서 4~6명 모둠이 각자 태블릿·휴대폰으로 같은 퍼즐 하나를 실시간으로 함께 맞추는 무료 수업 도구다. 학급 세우기·협동 연습과 자투리 시간 활동에 쓴다. 조각을 모둠원에게 나눠 주어 **모두가 참여해야 완성**되게 하는 것이 기존 서비스와 다른 핵심이다. 지금 교사들은 영어 화면에 사진 직접 업로드가 안 되고 모둠 배정이 번거로운 Jigsaw Explorer를 불편을 감수하며 쓰고 있다(조사: `docs/research.md`). 교사가 사진을 바로 올리고, 한 코드로 모둠을 나누고, 학생은 로그인 없이 들어오며, 광고·채팅·다른 게임이 없는 한국어 서비스를 만든다.

## 사용자

- 교사(진행자): 구글 로그인. 태블릿·PC, 모둠 한눈에 보기는 전자칠판에 띄움.
- 학생(초등): 로그인 없음. 태블릿(아이패드·갤럭시탭)과 스마트폰. 터치 조작.
- 같은 교실에 있어 대화는 말로 한다(화면 안 소통 기능 없음).

## MVP 범위

- F1: **수업 만들기** — 교사 구글 로그인. 그림 고르기(내장 그림 약 20장 / 내 그림 / 새로 올리기), 조각 수(12·24·48·70), 모둠 수를 정해 수업을 열면 숫자 6자리 코드와 QR을 보여 준다. '내 그림'은 교사만 보고 지울 수 있다.
- F2: **학생 입장** — 코드(또는 QR)와 이름만 입력해 들어온다. 교사가 모둠을 정하는 동안 대기 화면을 본다. 같은 기기로 다시 열면 같은 이름·모둠·조각 상자로 돌아온다.
- F3: **모둠 편성** — 대기실에 들어온 학생 이름이 나타나고, 교사가 모둠 칸으로 끌어 넣거나 '무작위로 나누기'를 누른다. '시작'을 누르면 모둠마다 퍼즐이 시작된다. 시작 후 들어온 학생도 교사가 모둠에 넣을 수 있다.
- F4: **모둠 협동 퍼즐** — 아래 '퍼즐 규칙' 전부. 조각 나눠 갖기, 잡기 잠금, 맞춤(딱 붙기), 끊김 처리, 완성 축하.
- F5: **모둠 한눈에 보기** — 교사 화면에 모둠별 판 축소판과 진행률(맞춘 조각 / 전체)을 격자로 보여 주고, 누르면 그 모둠을 크게 본다. '수업 끝내기'로 수업을 닫는다.

### 퍼즐 규칙 (F4 상세)

1. 시작 시 그 모둠 학생 수로 조각을 무작위로 고르게 나눈다(24조각·5명 → 5·5·5·5·4). 내 상자 조각은 나만 판으로 꺼낼 수 있다.
2. 판 위 조각(붙은 덩어리 단위)은 누구나 잡고 옮긴다. 잡으면 그 덩어리는 잡은 학생 몫이 되고, 다른 화면에는 그 학생 색 테두리로 보인다. 동시에 잡으면 서버에 먼저 닿은 쪽이 이긴다.
3. 놓으면 다른 화면에서는 새 자리로 미끄러지듯 이동한다(끄는 도중의 움직임은 보내지 않는다).
4. 맞는 이웃 조각이나 판의 제자리(틀) 가까이 놓으면 자석처럼 끌려가 딱 붙고 짧게 진동한다. 끄는 도중 붙을 자리에 가까워지면 미리 표시한다. 허용 거리는 조각 너비의 40%로 넉넉하게. 조각 회전 없음.
   - 판 가운데에 완성 자리 틀을 직소 조각 선으로 흐리게 그린다. 틀의 제자리에 들어간 조각(덩어리)은 **고정**되어 다시 움직일 수 없고, 고정된 조각에도 이웃 조각이 자석처럼 붙는다.
5. 판은 완성 그림의 약 3배 넓이(각 변 √3배). 꺼낸 조각은 틀 네 변 둘레에 고르게 나눠 놓는다. 처음엔 판이 비어 있고(틀만 보임) 조각은 모두 각자 상자에 있다. 터치에서 한 손가락은 조각만 움직이고, 판 확대·이동은 두 손가락으로만 한다(빈 곳을 한 손가락으로 끌어도 판이 움직이지 않음, 판이 화면 밖으로 밀려나지 않게 제한). 마우스는 빈 곳 끌기로 이동.
6. 잡은 채 10초 넘게 가만히 있거나 끊기면 그 덩어리는 자동으로 놓인다.
7. 끊긴 지 1분이 지나면 그 학생 상자에 남은 조각을 같은 모둠의 접속 중인 친구들에게 고르게 나눈다. 시작 후 들어온 학생은 상자 없이 판 위 조각만 만진다.
8. 모든 조각이 틀의 제자리에 고정되면(진행률 = 고정된 조각 수) 모둠원 모두에게 축하 화면·완성 그림·걸린 시간을 보여 주고, 교사 화면 그 모둠 칸에 '완성'을 표시한다. 모둠 간 순위는 보여 주지 않는다.
9. 학생은 '완성 그림 보기' 버튼으로 완성 그림을 작게 볼 수 있다.
10. **도움 설정(교사가 수업 만들 때 고름)**: 학년·목적에 맞게 난이도를 조절한다. 수업 안 모든 모둠에 같이 적용.
   - 들어갈 칸 미리 보기(끌 때 붙을 칸·변을 초록으로 표시): 기본 **꺼짐** (꺼져도 자석 붙기는 그대로)
   - 판의 조각 윤곽선(틀 안 칸 모양): 기본 켜짐 (끄면 틀 바깥 테두리만)
   - 완성 그림 보기 버튼: 기본 켜짐 (끄면 학생이 완성 그림을 볼 수 없음)
   - 틀 안 흐린 밑그림(완성 그림을 아주 흐리게 깔아 줌): 기본 꺼짐

## 범위 밖 (이번에 만들지 않는 것)

- 활동 기록(학생별 맞춘 조각 수, 모둠별 시간 저장), 전체 일시정지·힌트
- 반 전체 큰 퍼즐(20~30명 한 판), 모둠 대항전·순위
- 채팅·이모티콘·핑 등 화면 안 소통
- 끄는 도중 실시간 움직임 표시(메시지 한도 때문)
- 조각 회전, 테두리 조각 따로 모으기
- 완성 그림을 숨기는 '수수께끼 퍼즐', 영어 화면
- 학급 명단 저장, 학생 계정

## 완료 기준 (DoD)

- [ ] D1: 교사가 구글로 로그인해 그림·조각 수·모둠 수를 고르고 '수업 열기'를 누르면 6자리 코드와 QR이 표시된다
- [ ] D2: 교사가 올린 그림은 긴 변 2000px 이하 WebP로 줄고 EXIF가 제거된 채 비공개 저장소에 저장되며, '내 그림'에서 지우면 저장소 파일도 삭제된다
- [ ] D3: 학생이 코드와 이름을 입력하면 교사 대기실에 그 이름이 1초 안에 나타난다. 틀린 코드면 "코드를 다시 확인해 주세요"가 표시된다
- [ ] D4: 교사가 학생을 모둠 칸으로 끌거나 '무작위로 나누기'를 누른 뒤 '시작'을 누르면, 각 학생 화면에 자기 모둠 퍼즐과 자기 조각 상자가 나타난다
- [ ] D5: 조각이 모둠원 수로 고르게(최대 1개 차이) 나뉘고, 다른 학생 상자의 조각은 꺼낼 수 없다
- [ ] D6: 두 학생이 같은 덩어리를 동시에 잡으면 한 명만 성공하고, 다른 학생 화면에는 잡은 학생 색 테두리가 보인다
- [ ] D7: 맞는 이웃 조각을 허용 거리 안에 놓으면 모든 모둠원 화면에서 두 조각이 한 덩어리로 붙고, 이후 함께 움직인다. 서버(RPC)와 화면의 맞춤 판정이 같은 시험 사례에서 같은 결과를 낸다
- [ ] D8: 잡은 채 10초가 지나거나 연결이 끊기면 다른 학생이 그 덩어리를 잡을 수 있다
- [ ] D9: 학생 연결이 끊긴 지 1분이 지나면 그 학생 상자의 남은 조각이 같은 모둠 접속자들에게 나뉜다. 1분 안에 같은 기기로 돌아오면 원래 상자 그대로 이어진다
- [ ] D10: 마지막 조각이 붙으면 모둠원 모두에게 축하 화면과 걸린 시간이 표시되고, 교사 화면 그 모둠 칸에 '완성'이 표시된다
- [ ] D11: 교사 '모둠 한눈에 보기'에 모둠별 판 축소판과 진행률이 3초 안팎 간격으로 갱신되고, 모둠을 누르면 크게 보인다
- [ ] D12: 학생은 자기 모둠 데이터만 읽고 쓸 수 있다(다른 모둠·다른 수업 데이터 요청은 RLS로 거부된다)
- [ ] D13: 휴대폰(360px·390px), 태블릿(1024px), 데스크톱(1440px)에서 가로 넘침 없이 레이아웃이 깨지지 않고, 터치로 조각 꺼내기·옮기기·판 확대가 된다
- [ ] D14: 학생 개인정보를 저장하지 않는다 — 학생 이름은 DB·저장소에 쓰이지 않는다(Presence와 학생 기기에만 존재). 수업이 끝나면 학생 익명 계정과 모둠 배정이 삭제된다
- [ ] D15: 개인정보 처리방침 페이지가 있고 수집 항목·보관 기간·삭제 방법이 적혀 있다. 광고·외부 분석 스크립트가 없다

## 데이터

Supabase (Postgres + Auth + Storage + Realtime).

| 대상 | 저장 위치 | 내용 | 보관 |
|---|---|---|---|
| 교사 계정 | Supabase Auth | 구글 계정(이메일) | 탈퇴 시 삭제 |
| `images` | DB + 비공개 Storage 버킷 | 교사 그림 파일 경로, 가로·세로, 마지막 사용일 | 교사가 지울 때까지. 1년 미사용 시 자동 정리 |
| `sessions` | DB | 교사, 코드, 그림(내장 키 또는 images id), 조각 수, 시드, 상태(대기·진행·종료), 도움 설정 4가지 | 종료 후 30일 뒤 삭제 |
| `groups` | DB | 수업, 모둠 번호, 완성 시각 | 수업과 함께 |
| `members` | DB | 학생 익명 uid, 수업, 모둠, 색 번호, 마지막 신호 시각. **이름 없음** | 수업 종료 시 삭제(늦어도 24시간 뒤 자동) |
| `clusters` | DB | 붙은 덩어리: 모둠, 판 위 위치(x, y = 완성 그림 원점의 위치), z 순서, 제자리 고정 여부(locked), 잡은 uid, 잡은 시각 | 수업과 함께 |
| `pieces` | DB | 조각 번호(행·열), 속한 덩어리, 상자 주인 uid, 판 위 여부 | 수업과 함께 |
| 학생 이름 | Realtime Presence(메모리), 학생 기기 localStorage | 화면 표시용 | 저장하지 않음 |
| 내장 그림 | 정적 파일(Vercel) | 약 20장, 출처·라이선스 표기 | — |

- 회전이 없으므로 덩어리 안 조각의 상대 위치는 완성 그림에서의 위치와 같다. 위치는 덩어리당 (x, y) 하나만 저장한다. 두 덩어리가 이웃 조각을 가지고 (x, y) 차이가 허용 거리 안이면 합친다.
- 조각 모양은 `sessions.seed` 로 모든 기기에서 같게 계산한다(서버는 모양을 저장하지 않는다).
- 조각 변경은 모두 Postgres 함수(RPC)로만 한다: `take_from_tray`, `grab`, `drop`(맞춤 판정·합치기 포함), `redistribute_stale`, `heartbeat`. 함수가 결과를 `realtime.send` 로 모둠 비공개 채널에 방송한다.
- 교사 '한눈에 보기'는 실시간 구독 대신 3초마다 모둠 상태를 조회한다(메시지 한도 절약).

## 화면 목록

- 첫 화면: 학생 '코드 입력'이 가장 크게, 교사 '수업 만들기(로그인)'는 작게
- 교사 · 내 수업: 새 수업 만들기, 내 그림 관리
- 교사 · 수업 만들기: 그림 고르기(내장 / 내 그림 / 올리기), 조각 수, 모둠 수
- 교사 · 대기실: 코드·QR, 들어온 학생, 모둠 칸 끌어 넣기, 무작위로 나누기, 시작
- 교사 · 모둠 한눈에 보기: 모둠 격자(축소판·진행률·완성), 모둠 크게 보기, 학생 모둠 옮기기, 수업 끝내기
- 학생 · 들어오기: 코드, 이름
- 학생 · 기다리기: "선생님이 모둠을 정하고 있어요", 내 모둠 표시
- 학생 · 퍼즐: 위 판(확대·이동), 아래 내 조각 상자, 모둠원 이름·색, 진행률, 완성 그림 보기
- 학생 · 완성: 축하, 완성 그림, 걸린 시간
- 개인정보 처리방침

## 기술 스택

- 화면: 빌드 없는 순수 JavaScript(ES 모듈) 정적 사이트 + Canvas 2D, Vercel 배포. supabase-js는 CDN에서 불러온다.
  - 기본 스택(Next.js)에서 벗어나는 이유: 사용자가 운영 중인 종이접기 교실과 같은 방식이라 익숙하고, 화면 대부분이 캔버스라 React 이점이 적다.
- 서버: Supabase(Auth 구글·익명, Postgres RPC·RLS, Storage, Realtime Broadcast·Presence). 마이그레이션은 `supabase/migrations/*.sql`.
- 테스트: Vitest(맞춤 판정·조각 나누기·모양 생성 단위 테스트), 로컬 Supabase로 RPC·RLS 시험, Playwright(여러 브라우저 컨텍스트로 한 모둠 흉내).

## 위험 요소

- **Supabase 무료 한도**: 실시간 메시지는 보낸 1개 + 받은 사람 수만큼 센다. 추정(30명, 5초에 한 번 조작, 잡기·놓기를 모둠원 5명에게 방송)으로 한 반 수업 중 초당 약 60개 → 무료(초당 100개, 월 200만 개)로 동시에 한 반은 넉넉, 두 반은 빠듯, 월 약 12수업. Pro($25/월, 초당 500개, 월 500만 개)면 월 약 30수업, 그 이상 수업당 약 $0.4. 실측 필요.
- **무료 프로젝트 일시정지**: 1주일 활동이 없으면 멈춘다. 방학 뒤 첫 수업 전에 다시 켜야 한다. 사용자가 늘면 Pro.
- **학교망·기기 관리**: 학교망이 Supabase WebSocket을 막는지, 기기 관리(MDM)가 새 도메인을 '게임'으로 분류하는지 미확인 → 첫 시범 수업에서 확인. 화면 문구·주소를 수업 도구답게.
- **SQL 맞춤 판정**: 맞춤·합치기를 plpgsql로 구현해야 하고, 화면 쪽 JS 판정과 결과가 같아야 한다 → 같은 시험 사례 표로 양쪽을 검사.
- **저사양 태블릿 성능**: 70조각 + 확대·이동에서 프레임이 떨어질 수 있음 → 조각 비트맵 캐시, devicePixelRatio 상한 2.
- **학생 얼굴 사진**: 교사가 올리는 학급 사진은 교사 책임. 올리기 화면에 "학생 얼굴 사진은 학교 방침을 확인하세요" 안내.
- **학습지원 소프트웨어 심의(2026.3~)**: 학생 개인정보를 저장하지 않는 구조라 대상에서 빠질 여지가 크지만 단정할 수 없음 → 처리방침에 근거를 명확히.
- **내장 그림 저작권**: 공공누리 1유형·CC0 등 출처를 확인한 그림만 쓰고 출처를 표기.
