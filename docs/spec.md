# 모둠 협동 직소 퍼즐 (가칭: 함께 퍼즐)

트랙: 교육
종류: 새 서비스 (2026-10-08 서버·데이터 구조 변경 — 아래 '구조 변경 기록')

## 목적

초등 교실에서 4~6명 모둠이 각자 태블릿·휴대폰으로 같은 퍼즐 하나를 실시간으로 함께 맞추는 무료 수업 도구다. 학급 세우기·협동 연습과 자투리 시간 활동에 쓴다. 조각을 모둠원에게 나눠 주어 **모두가 참여해야 완성**되게 하는 것이 기존 서비스와 다른 핵심이다. 지금 교사들은 영어 화면에 사진 직접 업로드가 안 되고 모둠 배정이 번거로운 Jigsaw Explorer를 불편을 감수하며 쓰고 있다(조사: `docs/research.md`). 교사가 사진을 바로 올리고, 한 코드로 모둠을 나누고, 학생은 로그인 없이 들어오며, 광고·채팅·다른 게임이 없는 한국어 서비스를 만든다.

## 사용자

- 교사(진행자): 구글 로그인(gyosil 공용 계정). 태블릿·PC, 모둠 한눈에 보기는 전자칠판에 띄움.
- 학생(초등): 로그인 없음. 태블릿(아이패드·갤럭시탭)과 스마트폰. 터치 조작.
- 같은 교실에 있어 대화는 말로 한다(화면 안 소통 기능 없음).

## MVP 범위

- F1: **수업 만들기** — 교사 구글 로그인(처음이면 '함께 퍼즐 시작하기' 동의, gyosil 공용 규칙). 그림 고르기(내장 그림 약 20장 / 내 그림 / 새로 올리기), 조각 수(12·24·48·70), 모둠 수를 정해 수업을 열면 숫자 6자리 코드와 QR을 보여 준다. '내 그림'은 교사만 보고 지울 수 있다.
- F2: **학생 입장** — 코드(또는 QR)와 이름만 입력해 들어온다. 교사가 모둠을 정하는 동안 대기 화면을 본다. 같은 기기로 다시 열면 같은 이름·모둠·조각 상자로 돌아온다.
- F3: **모둠 편성** — 대기실에 들어온 학생 이름이 나타나고, 교사가 모둠 칸으로 끌어 넣거나 '무작위로 나누기'를 누른다. '시작'을 누르면 모둠마다 퍼즐이 시작된다. 시작 후 들어온 학생도 교사가 모둠에 넣을 수 있다.
- F4: **모둠 협동 퍼즐** — 아래 '퍼즐 규칙' 전부. 조각 나눠 갖기, 잡기 잠금, 맞춤(딱 붙기), 끊김 처리, 완성 축하.
- F5: **모둠 한눈에 보기** — 교사 화면에 모둠별 판 축소판과 진행률(맞춘 조각 / 전체)을 격자로 보여 주고, 누르면 그 모둠을 크게 본다. '수업 끝내기'로 수업을 닫는다.

### 퍼즐 규칙 (F4 상세)

1. 시작 시 그 모둠 학생 수로 조각을 무작위로 고르게 나눈다(24조각·5명 → 5·5·5·5·4). 내 상자 조각은 나만 판으로 꺼낼 수 있다.
2. 판 위 조각(붙은 덩어리 단위)은 누구나 잡고 옮긴다. 잡으면 그 덩어리는 잡은 학생 몫이 되고, 다른 화면에는 그 학생 색 테두리로 보인다. 동시에 잡으면 서버에 먼저 닿은 쪽이 이긴다.
3. 놓으면 다른 화면에서는 새 자리로 미끄러지듯 이동한다(끄는 도중의 움직임은 보내지 않는다).
4. 맞는 이웃 조각이나 판의 제자리(틀) 가까이 놓으면 자석처럼 끌려가 딱 붙고 짧게 진동한다. 끄는 도중 붙을 자리에 가까워지면 미리 표시한다. 허용 거리는 조각 너비의 40%로 넉넉하게. 조각 회전 없음.
   - 판 가운데에 완성 자리 틀을 직소 조각 선으로 흐리게 그린다. 틀의 제자리에 들어간 조각(덩어리)은 **고정**되어 다시 움직일 수 없고, 고정된 조각에도 이웃 조각이 자석처럼 붙는다.
5. 판은 완성 그림의 약 3배 넓이(각 변 √3배). 꺼낸 조각은 틀 네 변 둘레에 고르게 나눠 놓는다. 처음엔 판이 비어 있고(틀만 보임) 조각은 모두 각자 상자에 있다. 터치에서 한 손가락은 조각만 움직이고, 판 확대·이동은 두 손가락으로만 한다(빈 곳을 한 손가락으로 끌어도 판이 움직이지 않음, 판이 화면 밖으로 밀려나지 않게 제한). 마우스는 빈 곳 끌기로 이동.
6. 잡은 채 10초 넘게 가만히 있거나 끊기면 그 덩어리는 자동으로 놓인다.
7. 끊긴 지 1분이 지나면 그 학생 상자에 남은 조각을 같은 모둠의 접속 중인 친구들에게 고르게 나눈다. 시작 후 들어온 학생은 상자 없이 판 위 조각만 만진다.
8. 모든 조각이 틀의 제자리에 고정되면(진행률 = 고정된 조각 수) 모둠원 모두에게 축하 화면·완성 그림·걸린 시간을 보여 주고, 교사 화면 그 모둠 칸에 '완성'을 표시한다. 모둠 간 순위는 보여 주지 않는다.
9. 학생은 '완성 그림 보기' 버튼으로 완성 그림을 작게 볼 수 있다.
10. **도움 설정(교사가 수업 만들 때 고름)**: 학년·목적에 맞게 난이도를 조절한다. 수업 안 모든 모둠에 같이 적용.
   - 들어갈 칸 미리 보기(끌 때 붙을 칸·변을 초록으로 표시): 기본 **꺼짐** (꺼져도 자석 붙기는 그대로)
   - 판의 조각 윤곽선(틀 안 칸 모양): 기본 켜짐 (끄면 틀 바깥 테두리만)
   - 완성 그림 보기 버튼: 기본 켜짐 (끄면 학생이 완성 그림을 볼 수 없음)
   - 틀 안 흐린 밑그림(완성 그림을 아주 흐리게 깔아 줌): 기본 꺼짐

위 규칙·모둠 편성·한눈에 보기 등 화면 동작은 이번 구조 변경으로 바뀌지 않는다. 바뀌는 것은 '누가 판정하고 어디에 저장하는가'뿐이다.

## 범위 밖 (이번에 만들지 않는 것)

- 활동 기록(학생별 맞춘 조각 수, 모둠별 시간 저장), 전체 일시정지·힌트
- 반 전체 큰 퍼즐(20~30명 한 판), 모둠 대항전·순위
- 채팅·이모티콘·핑 등 화면 안 소통
- 끄는 도중 실시간 움직임 표시(서버로 바뀌어 메시지 한도는 없어졌지만, 저사양 기기·학교망 부담과 범위 때문에 이번에도 하지 않음)
- 조각 회전, 테두리 조각 따로 모으기
- 완성 그림을 숨기는 '수수께끼 퍼즐', 영어 화면
- 학급 명단 저장, 학생 계정
- rt 서버 여러 대로 나누기(수평 확장), 무중단 배포, 자동 배포(GitHub Actions 등 — 선택 사항으로 나중에)
- gyosil 계정 삭제(`auth.users` 삭제). jigsaw 탈퇴는 jigsaw 데이터만 지운다
- 교사 탈퇴 화면 기능. 탈퇴는 처리방침에 적힌 문의 메일로 요청받아 운영자가 수동으로 처리한다(절차는 `docs/ops.md`)

## 완료 기준 (DoD)

- [ ] D1: 교사가 구글로 로그인하고(처음이면 '함께 퍼즐 시작하기' 동의 후) 그림·조각 수·모둠 수를 고르고 '수업 열기'를 누르면 6자리 코드와 QR이 표시된다. `jigsaw.teachers` 에 없는 계정은 수업을 열 수 없다(서버가 거부)
- [ ] D2: 교사가 올린 그림은 브라우저에서 긴 변 2000px 이하 WebP로 줄고 EXIF가 제거된 뒤 rt 서버를 거쳐 비공개 버킷 `jigsaw-images` 에 저장된다. 화면은 서버가 발급한 서명 URL로만 그림을 본다. '내 그림'에서 지우면 저장소 파일도 삭제되고, 열린 수업에서 쓰는 그림은 서버가 지우기를 거부한다
- [ ] D3: 학생이 코드와 이름을 입력하면 교사 대기실에 그 이름이 1초 안에 나타난다. 틀린 코드면 "코드를 다시 확인해 주세요"가 표시된다
- [ ] D4: 교사가 학생을 모둠 칸으로 끌거나 '무작위로 나누기'를 누른 뒤 '시작'을 누르면, 각 학생 화면에 자기 모둠 퍼즐과 자기 조각 상자가 나타난다
- [ ] D5: 조각이 모둠원 수로 고르게(최대 1개 차이) 나뉘고, 다른 학생 상자의 조각을 꺼내려는 요청은 서버가 거부한다
- [ ] D6: 두 학생이 같은 덩어리를 동시에 잡으면 서버에 먼저 도착한 한 명만 성공하고, 다른 학생 화면에는 잡은 학생 색 테두리가 보인다
- [ ] D7: 맞는 이웃 조각을 허용 거리 안에 놓으면 모든 모둠원 화면에서 두 조각이 한 덩어리로 붙고, 이후 함께 움직인다. 서버는 화면과 같은 `public/js/puzzle/snap.js`·`geometry.js` 를 실행해 판정하며, 공용 사례 표(`tests/fixtures/snap-cases.json`)를 서버의 놓기 처리 경로로 넣어도 모두 기대 결과와 같다
- [ ] D8: 잡은 채 10초가 지나거나 연결이 끊기면(소켓 끊김 감지 약 15초 이내) 다른 학생이 그 덩어리를 잡을 수 있다
- [ ] D9: 학생 연결이 끊긴 지 1분이 지나면 그 학생 상자의 남은 조각이 같은 모둠 접속자들에게 나뉜다. 1분 안에 같은 기기(저장된 학생 토큰)로 돌아오면 원래 이름·모둠·상자 그대로 이어진다
- [ ] D10: 마지막 조각이 고정되면 모둠원 모두에게 축하 화면과 걸린 시간이 표시되고, 교사 화면 그 모둠 칸에 '완성'이 표시된다
- [ ] D11: 교사 '모둠 한눈에 보기'에 모둠별 판 축소판과 진행률이 변경 후 3초 안에 반영되고(서버가 소켓으로 보냄), 모둠을 누르면 크게 보인다
- [ ] D12: 학생은 자기 수업·자기 모둠에만 작용한다 — 다른 모둠·다른 수업을 대상으로 한 소켓 메시지·HTTP 요청은 서버가 거부한다. 교사는 자기 수업·자기 그림만 다룬다. 브라우저는 Supabase DB·Storage에 직접 접속하지 않고, 공개(anon)·로그인(authenticated) 키로는 `jigsaw` 스키마와 `jigsaw-images` 버킷에 접근할 수 없다(로컬 Supabase 시험)
- [ ] D13: 휴대폰(360px·390px), 태블릿(1024px), 데스크톱(1440px)에서 가로 넘침 없이 레이아웃이 깨지지 않고, 터치로 조각 꺼내기·옮기기·판 확대가 된다
- [ ] D14: 학생 개인정보를 저장하지 않는다 — 학생 이름은 DB·Storage·서버 로그에 쓰이지 않는다(rt 서버 메모리와 학생 기기에만 존재). 학생은 Supabase 계정을 만들지 않는다. 수업이 끝나면(늦어도 시작 24시간 뒤 자동) 모둠 배정 행이 삭제되고 학생 토큰은 무효가 된다
- [ ] D15: 개인정보 처리방침 페이지가 있고 수집 항목·보관 기간·삭제 방법·처리 장소(Vercel, AWS Lightsail 서울, Supabase 서울)가 적혀 있다. 광고·외부 분석 스크립트가 없고, CSP가 허용하는 외부 주소는 rt 서버·구글 로그인(GIS)·그림 서명 URL 주소(Supabase Storage)·Pretendard 글꼴 CSS·글꼴 파일 주소(`https://cdn.jsdelivr.net`, `style-src`·`font-src` 만)뿐이다
- [ ] D16: rt 서버는 허용된 출처(`https://jigsaw.gyosil.app`, 로컬 개발 주소)가 아닌 HTTP·소켓 요청을 거부하고, 요청·소켓 메시지 빈도와 열린 수업·연결 수가 상한을 넘으면 거부한다. service_role 키는 화면 파일·서버 응답·저장소 어디에도 없다
- [ ] D17: `https://rt.gyosil.app/health` 가 응답하고, 서버 프로세스가 죽으면 systemd가 다시 띄운다. 다시 뜬 뒤 진행 중이던 수업은 마지막 저장 상태(최대 수 초 전)로 이어지고 학생·교사 화면은 같은 기기로 자동 재접속한다(잡기는 모두 놓인 상태, 학생 이름은 재접속한 화면이 다시 보내 복구)

## 시스템 구조

```
학생·교사 브라우저 ──정적 파일──> Vercel (jigsaw.gyosil.app)
        │
        ├─ HTTPS API + socket.io (wss) ──> rt.gyosil.app : Lightsail 서울 (Caddy → Node 24, localhost:3400)
        │                                        │ service_role (서버만)
        │                                        └──> Supabase gyosil (서울): DB 스키마 jigsaw, Storage jigsaw-images, Auth(교사)
        ├─ 구글 로그인 버튼 ──> Google Identity Services
        └─ 그림 읽기 ──> 서버가 발급한 서명 URL (Supabase Storage)
```

- **판정 권위 = rt 서버 메모리.** 수업·모둠·덩어리·조각·잡기·접속 상태를 서버가 메모리에 들고 한 프로세스에서 차례로 처리한다(같은 모둠의 동작은 도착 순서대로). 퍼즐 규칙은 `public/js/puzzle/snap.js`·`geometry.js` 를 서버가 그대로 import 해서 실행한다 → SQL 판정 함수와 JS·SQL 일치 시험은 없앤다.
- **브라우저는 Supabase에 직접 접속하지 않는다**(그림 서명 URL 읽기만 예외). supabase-js 를 화면에서 쓰지 않는다.
- **실시간**: socket.io. 방(room)은 수업·모둠·교사 단위. 잡기·놓기(합치기·고정 포함)·꺼내기·상자 나눔·완성·모둠원 접속 상태를 해당 모둠 방에 보낸다. 같은 모둠 방송은 0.1초 이내로 묶어 보낸다(그 모둠 학생에게 응답·state 를 보내기 전에는 묶음을 먼저 보냄). 교사 한눈에 보기는 서버가 변경된 모둠 요약을 1초 이내 간격으로 묶어 교사 방에 보낸다(폴링 없음). 학교망이 WebSocket을 막으면 socket.io 의 HTTP 롱폴링으로 자동 대체된다.
- **접속·끊김**: 기존 heartbeat RPC 대신 소켓 연결 상태를 쓴다(socket.io ping 간격을 짧게 해 끊김을 약 15초 안에 감지). 끊기면 잡은 덩어리를 바로 놓고, 끊긴 지 1분 뒤 상자를 나눈다(서버 타이머). 화면이 숨겨지면(visibilitychange) 화면이 스스로 놓기를 보낸다.
- **학생 세션**: 코드+이름 → 서버가 무작위 학생 토큰을 발급(DB에는 해시만). 학생 기기는 토큰과 이름을 수업 코드별 localStorage 에 저장해 두고(탭·브라우저를 닫았다 열어도 복귀, 수업이 끝나면 화면이 지움) 재접속 때 함께 보낸다. 토큰은 수업이 열려 있는 동안만 유효하다. 이름은 서버 메모리에만 있고 DB에 쓰지 않는다. 서버가 재시작되어 메모리의 이름이 사라져도 학생 화면이 재접속하며 이름을 다시 보내 복구된다.
- **교사 인증**(platform.md 2.2, 확정): 화면에 Google Identity Services 버튼을 띄우고, 받은 ID 토큰과 nonce를 rt 서버로 보낸다. 서버가 Supabase `signInWithIdToken`(nonce 포함)으로 교사 uid를 확인하고 `jigsaw.teachers` 소속을 본 뒤, 서버가 서명한 교사 세션 토큰(만료 있음)을 돌려준다. 이후 HTTP·소켓 요청은 이 토큰으로 인증한다. `jigsaw.teachers` 에 없으면 '함께 퍼즐 시작하기'(이름·약관 동의, `core.profiles` 공용 정보 사용) 화면을 거쳐 행을 만든다.
- **그림**: 업로드는 브라우저 변환(WebP·EXIF 제거) → 서버(크기·형식 검사: WebP 서명, 3MB 이하, 긴 변 2000px 이하) → Storage `jigsaw-images/<teacher_uid>/<image_id>.webp` (service_role). 보기는 서버가 짧은 만료의 서명 URL을 발급. 그림 삭제는 서버가 열린 수업 사용 여부를 확인한 뒤 Storage API로 지운다(단일 서버라 확인과 삭제 사이 경쟁이 없다).
- **정리 작업**: pg_cron 대신 서버 내부 주기 작업(예: 10분마다). 시작 24시간 지난 열린 수업 자동 종료, 종료된 수업의 members 삭제, 종료 30일 지난 sessions 삭제. `auth.users` 는 지우지 않는다(학생 계정 자체가 없음). 공용 프로젝트에 확장을 추가하지 않는다.
- **HTTP API**(세부 경로는 plan에서): `GET /health`, 교사 로그인·시작하기, 내 그림 목록·올리기·지우기·서명 URL, 수업 만들기·내 수업 목록, 학생 입장(코드+이름 → 토큰). 대기실·편성·시작·퍼즐 조작·한눈에 보기·끝내기는 소켓 메시지로.

- 회전이 없으므로 덩어리 안 조각의 상대 위치는 완성 그림에서의 위치와 같다. 위치는 덩어리당 (x, y) 하나. 두 덩어리가 이웃 조각을 가지고 (x, y) 차이가 허용 거리 안이면 합친다.
- 조각 모양은 `sessions.seed` 로 모든 기기와 서버에서 같게 계산한다(모양은 저장하지 않는다).
- 기존 `clusters`·`pieces` 테이블은 `groups` 의 jsonb 사본 하나로 대신한다(모둠당 한 행만 쓰면 되어 저장 횟수가 줄고, 판정이 DB에 없으므로 행 단위 잠금이 필요 없다).
- 저장 시점(write-behind): 수업 만들기·입장(members 행)·편성·시작·완성·끝내기는 즉시, 판 변경은 모둠별로 묶어 최대 2초에 한 번. 서버가 뜰 때 열린 수업(대기·진행)을 DB에서 읽어 메모리에 복구한다. 종료 신호(SIGTERM)를 받으면 남은 저장을 마치고 끝난다.
- 마이그레이션: `supabase/migrations/*_jigsaw_*.sql`. 원격 적용은 `SUPABASE_DB_URL=… bash scripts/db/migrate.sh` 로 파일마다 한 번만 적용하고 `jigsaw.schema_migrations` 에 기록한다(`supabase db push`·`config push`·원격 `db reset` 금지). 로컬은 기존처럼 `npx supabase` 로컬 스택.

## 기술 스택

- 화면: 빌드 없는 순수 JavaScript(ES 모듈) 정적 사이트 + Canvas 2D, Vercel 배포. socket.io 클라이언트는 고정 버전 ESM 파일을 `public/js/vendor/` 에 둔다(외부 CDN·rt 서버에서 스크립트를 불러오지 않음). supabase-js 는 화면에서 쓰지 않는다.
  - 기본 스택(Next.js)에서 벗어나는 이유: 사용자가 운영 중인 종이접기 교실과 같은 방식이라 익숙하고, 화면 대부분이 캔버스라 React 이점이 적다.
- 실시간·판정 서버(`server/`, 같은 저장소): Node 24, 빌드 없는 JavaScript(ES 모듈, 화면의 퍼즐 모듈을 그대로 import), `node:http` + socket.io, `@supabase/supabase-js`(service_role, 서버 전용). 서버 의존성은 `server/package.json` 에 따로 두어 서버에서 운영 의존성만 설치한다.
  - 기본 스택(Vercel)에서 벗어나는 이유: 소켓 연결을 오래 유지하고 수업 상태를 메모리에 들고 있어야 해서 서버리스로는 안 된다.
- 운영: AWS Lightsail 서울, Ubuntu 24.04, 1GB, Caddy(HTTPS 자동, `rt.gyosil.app` → `localhost:3400` reverse_proxy), systemd(자동 재시작). 비밀값은 `/etc/jigsaw-rt.env`(권한 600, 저장소에 넣지 않음): `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_ANON_KEY`(signInWithIdToken 용), `SESSION_SECRET`, `GOOGLE_CLIENT_ID`, `ALLOWED_ORIGINS`. 설치 스크립트 `scripts/rt/setup.sh`(Node·Caddy·systemd 유닛·로그 보관 설정), 배포는 서버에서 `git pull` + 의존성 설치 + 재시작(`scripts/rt/deploy.sh`). Lightsail 자동 스냅숏 켬. 비용 월 약 $7(Lightsail 1GB) + 스냅숏 소액.
- 보안
  - CSP: `connect-src 'self' https://rt.gyosil.app wss://rt.gyosil.app` + 구글 로그인 주소 + 그림 서명 URL용 Supabase Storage 주소, `script-src` 에 `https://accounts.google.com/gsi/client`, `frame-src` 에 구글 로그인, `style-src`·`font-src` 에 Pretendard 글꼴용 `https://cdn.jsdelivr.net`(지금 `index.html`·`privacy.html` 이 쓰는 그대로, 자체 호스팅은 하지 않음. 스크립트는 jsDelivr 에서 받지 않는다). 로컬 개발 주소는 로컬에서만.
  - 서버: 허용 Origin 목록(`https://jigsaw.gyosil.app` + 로컬)만 CORS·소켓 허용. 요청 본문·소켓 메시지 크기 상한, IP·연결별 빈도 제한. **학교는 한 반 30명 이상이 공인 IP 하나로 들어오므로** IP별 한도는 넉넉히(예: 연결 IP당 200), 학생 단위 제한은 연결·토큰 기준으로. 틀린 코드 입력은 IP당 짧은 시간 반복 시 잠시 거부(코드 추측 방지). 열린 수업 수 상한(예: 100), 전체 연결 수 상한(예: 3000). 교사 토큰은 서버 `SESSION_SECRET` 으로 서명, 학생 토큰은 무작위 값(DB엔 해시).
  - 서버 코드는 `jigsaw` 스키마 클라이언트만 만든다(다른 앱 스키마 접근 금지).
- 테스트
  - Vitest 단위: 기존 퍼즐 모듈 시험 유지 + 서버 수업·모둠 상태 로직(조각 나누기, 잡기 경쟁, 놓기·합치기·고정, 10초·1분 타이머(가짜 시계), 재분배, 완성, 권한 거부)을 소켓 없이 직접 시험. 공용 사례 표를 서버 놓기 경로로 통과(D7).
  - 서버 통합(Vitest + 로컬 Supabase + 로컬 rt 서버): 소켓 클라이언트 여러 개로 동시 잡기, 다른 모둠 메시지 거부, Origin·빈도 제한, write-behind 저장·재시작 복구, 정리 작업, DB 전체에 학생 이름 문자열 없음, anon·authenticated 키로 `jigsaw` 스키마·버킷 접근 거부.
  - 없애는 시험: RLS·Realtime 정책·RPC·`snap-parity`(JS·SQL 일치)·익명 계정 정리 시험(`tests/db/*` 대부분). 남길 만한 것은 서버 통합 시험으로 옮긴다.
  - Playwright E2E: 정적 서버 + 로컬 rt 서버 + 로컬 Supabase. 교사 로그인은 로컬 전용 시험 교사 토큰 발급(운영에서는 꺼짐, 환경변수로만 켬)으로 대신하고, 실제 구글 로그인은 배포 뒤 사용자와 확인. 기존 E2E 흐름(입장·편성·협동·끊김·완성·한눈에 보기·4개 너비·CSP)을 새 구조로 다시 통과.

- 실시간·판정 서버: `https://rt.gyosil.app` / `wss://rt.gyosil.app` (Lightsail 서울, A 레코드·Caddy 인증서·`/health` 확인 완료)

## 위험 요소

- **서버 한 대 = 단일 장애점**: Lightsail 이 멈추면 모든 수업이 멈춘다. 배포(재시작)도 수업 중이면 끊김을 만든다 → write-behind 재시작 복구와 "다시 연결하는 중" 자동 재접속, 배포는 수업 시간 밖에. 1GB 메모리: 수업 하나는 수 MB 수준이라 동시 수십 수업은 여유가 있을 것으로 보지만 실측 필요(Node `--max-old-space-size` 지정, 스왑 1GB 설정).
- **Supabase 무료 일시정지(7일 미사용)**: gyosil 공용 규칙대로 모니터링. rt 서버의 주기 정리 작업이 DB 요청을 보내므로 활동으로 잡힐 가능성이 높지만 확인 필요.
- **백업**: Lightsail 스냅숏은 서버만 담는다. DB는 platform.md 2.5 대로 `jigsaw` 스키마를 매일 `pg_dump` 로 백업한다(T24 에서 스크립트·문서, T25 에서 설정).
- **Data API 노출**: `jigsaw` 를 Exposed schemas 에 넣으므로, 실수로 anon·authenticated 에 권한을 주면 바로 공개된다 → 마이그레이션에 권한 회수(`revoke`)를 명시하고 D12 시험으로 막는다. 공용 프로젝트의 기본 권한(default privileges)이 새 테이블에 권한을 자동으로 줄 수 있으므로 테이블마다 회수를 확인한다.
- **학교망·기기 관리**: 학교망이 `rt.gyosil.app` WebSocket 을 막거나 MDM이 새 도메인을 막는지 미확인 → socket.io 롱폴링 대체, 첫 시범 수업에서 확인. 화면 문구·주소를 수업 도구답게.
- **화면 모듈을 서버에서 실행**: `snap.js`·`geometry.js` 가 DOM·브라우저 전용 API(Path2D 등)에 의존하면 Node 에서 깨진다 → 판정에 쓰는 부분을 순수 함수로 유지하고, 서버 import 시험을 둔다.
- **교사 토큰 저장**: 서버가 발급한 교사 토큰을 브라우저에 저장하므로 XSS 에 약하다 → 엄격한 CSP, 외부 스크립트는 구글 로그인만, 만료(예: 12시간).
- **잡기 연장 악용**: 화면이 움직이는 동안 잡기를 연장하는데, 조작된 화면이 계속 붙잡을 수 있다 → 서버에서 한 번 잡은 뒤 최대 연장 시간을 둘지 plan에서 정한다.
- **보류 중인 T14a 변경**: 작업 트리의 `jigsaw`/`jigsaw_private` 스키마·RPC·Realtime·Storage 정책 마이그레이션은 새 구조와 충돌한다. 원격에 적용되지 않았으므로 SQL 마이그레이션은 버리고 새 마이그레이션 묶음으로 다시 쓴다(확정). 화면 쪽 변경은 쓸 부분만 골라 옮긴다(plan).
- **gyosil 대시보드 작업이 바뀜**: 익명 로그인 켜기·익명 가입 한도 상향·Redirect URL 추가는 더 이상 필요 없다. 대신 Google OAuth 클라이언트의 승인된 JavaScript 원본에 `https://jigsaw.gyosil.app` 추가가 필요하다.
- **저사양 태블릿 성능**: 70조각 + 확대·이동에서 프레임이 떨어질 수 있음 → 조각 비트맵 캐시, devicePixelRatio 상한 2.
- **학생 얼굴 사진**: 교사가 올리는 학급 사진은 교사 책임. 올리기 화면에 "학생 얼굴 사진은 학교 방침을 확인하세요" 안내.
- **개인정보 처리방침·학습지원 소프트웨어 심의(2026.3~)**: 학생 개인정보를 저장하지 않는 구조라 대상에서 빠질 여지가 크지만 단정할 수 없음. 처리방침에 처리 장소와 위탁을 적는다: 화면 제공 Vercel(접속 기록, 해외 처리 가능), 실시간 서버 AWS Lightsail 서울(학생 이름은 수업 중 메모리에서만, IP는 요청 제한용으로 메모리에서만), 데이터 저장 Supabase(AWS 서울 리전, 교사 이메일·그림·수업 정보). 학생 이름이 서버 메모리를 거쳐 가는 점(이전 구조는 Realtime Presence 메모리)을 그대로 밝힌다.
- **내장 그림 저작권**: 공공누리 1유형·CC0 등 출처를 확인한 그림만 쓰고 출처를 표기.
